# 운영자 오프라인 읽기

- 운영자 로그인 → 운영자 메뉴 → 통계·자료 → 오프라인 읽기 (`/insights/offline`).
- 제목·설명 검색으로 기사를 선택하거나 연재 전체 선택을 사용한다. 한 파일당 최대 30편이다.
- 선택 기사 오프라인 파일 저장을 누르면 본문·이미지·도표를 담은 HTML 파일이 다운로드된다.
- 기기의 다운로드 폴더에서 브라우저로 파일을 열어 읽는다. 파일 안의 기사 목록으로 이동할 수 있다.
- 수정본이 필요하면 같은 기사를 다시 내려받고 이전 파일은 파일 앱에서 삭제한다. 사이트 로그아웃으로 다운로드 파일을 삭제할 수는 없다.
- 동영상·외부 출처·온라인 원문 링크는 인터넷 연결이 필요하다.

## 접근과 데이터 범위

일반 메뉴와 기사에는 저장 기능을 노출하지 않는다. 운영자 메뉴와 페이지는 기존 `app_metadata.seed_role === 'owner'` 규칙을 사용한다. 목록 로드·다운로드 시작·파일 생성 직전에 Auth 서버의 현재 사용자 ID와 운영자 역할을 확인한다. 로컬 저장소의 역할만으로 파일 생성을 허용하지 않는다. 계정 변경이나 화면 이탈은 진행 중인 저장을 취소한다.

공개 기사 목록만 사용하며, 원고함·비공개 첨부파일·회원 기록은 읽지 않는다. 본문은 로그인된 동일 출처 iframe의 실제 기사 화면에서 가져오며 검색엔진용 대체 본문은 사용하지 않는다. HTML 허용 목록으로 다시 구성하고 댓글·입력폼·스크립트·임베드·이벤트 속성을 제외한다. 그림은 파일 내부 데이터로 저장한다. 누락된 그림이나 본문이 있으면 완료 파일을 만들지 않는다. 작은 UI 아이콘을 제외한 SVG 도표는 격리된 이미지로 보존한다.

오프라인 파일에는 인증 토큰이나 앱 실행 코드가 없다. CSP는 외부 리소스 로드를 차단한다. 별도 서비스 워커나 공개 페이지 캐시를 추가하지 않으므로 홈페이지의 최신 기사·이미지 갱신 방식에 영향을 주지 않는다. 이미 내려받은 공개 기사 파일의 열람은 온라인 로그인 상태와 별개다.

## 검증

- TypeScript 전체 검사와 전체 프로덕션 빌드.
- 비로그인 브라우저에서 목록·선택·저장 버튼이 차단되는지 확인.
- DOM 검사: 다른 창의 노드에서 본문·인용 링크·표·이미지·SVG 도표 보존, 댓글·폼·스크립트·이벤트 속성 제거, 이미지 내장과 파일 CSP 확인.
- Auth 응답 검사: 비로그인·일반 회원·다른 사용자 ID 거부, 동일 ID의 운영자만 허용.
- 취소 시 iframe 정리와 외부 사이트 캡처 거부 확인.
- 실제 운영자 계정에서 기사 1편 저장 후 비행기 모드에서 파일을 다시 열어 본문과 그림을 확인하는 최종 기기 점검을 권장한다.
