# 댓글·씨야 답글 관리

- 운영자 진입: `/insights`, 댓글 관리: `/insights/comments`.
- 공개 `/forum`은 유지한다. 운영자는 모든 기사 댓글을 관리 화면에서 읽고 답글을 처리한다.
- 새 사이트 댓글은 DB 트리거가 비공개 초안 대기열에 넣는다. 매분 실행하는 `seed-comment-drafts` 작업이 최대 3건씩 씨야 초안을 만든다. 댓글의 핵심 의견과 게시 기사 본문을 함께 읽으며, 기사 본문을 찾지 못하면 실패 상태로 남긴다.
- 운영자 상단 ‘새 댓글’ 배지는 미확인 댓글 수를 보여주고 30초마다 갱신한다. 이는 사이트 안의 알림이며 이메일·SNS 알림은 보내지 않는다.
- 댓글 선택 시 확인 처리. 초안을 수정해 저장하거나 다시 생성·보류할 수 있다. **‘승인하고 게시’만 공개 답글을 등록한다.** 대기열의 초안과 참고 기사 본문은 운영자만 조회할 수 있다.
- 답글은 원댓글 바로 아래에 ‘씨야 · AI · 운영자 승인 답글’로 표시한다. 승인한 운영자 ID, 승인된 문장과 답글 ID가 대기열에 남는다. 게시 RPC는 행 잠금과 유일 인덱스로 중복 게시를 막는다.
- 씨야 답글은 다시 초안 대기열에 들어가지 않는다. 실패는 화면에서 직접 다시 생성하며, 작업 중단은 10분 후 회수하고 최대 3회 시도한다.
- SNS 댓글은 이 화면에 포함하지 않는다. 별도 댓글 조회 연결이 필요하다.

## 인증·복구

- Edge Function `siya-comment-replies`는 운영자 요청에 Auth 서버 검증을 사용한다. 내부 cron 요청은 Vault 토큰을 서비스 전용 RPC로 검증한다. 공개 JWT 검증을 끈 이유는 cron 인증이며, 익명 요청은 거절한다.
- Vault·서비스 키·OpenAI 키는 서버에서만 사용하며 클라이언트에 노출하지 않는다.
- 설치 SQL: `supabase/comment-reply-desk.sql`. 자동 작업: `seed-comment-drafts`.
- 이번 변경 전 로컬 주석 태그와 원격 `restore/20261004-1255-comment-desk` 복구 브랜치를 남겼다. CLI 인증이 제공되지 않아 원격 태그 업로드는 할 수 없었으며, 연결된 GitHub API로 현재 main의 복구 브랜치를 보존했다.
